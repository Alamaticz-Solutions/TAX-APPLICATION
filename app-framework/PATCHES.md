### Patch 1: Finding N Fix — `jsonb[]` Null Parameter Binding

- **Tag:** `pinned/local-patch-1`
- **Commit:** `6ee6985b7d357a54fb9eddb456da50654ce87c3d`
- **Crate Affected:** `appfw_provider_postgres` (`appfw_provider_postgres/src/param.rs`)
- **Upstream Status:** **MUST UPSTREAM TO PDS** (Required before next framework upgrade / release baseline re-pin)

#### Problem Description
When executing PostgreSQL queries generated by `app_gen` or dynamic mutations where a `jsonb[]` column (represented in the runtime as `RuntimeDataType::ObjectArray` or `RuntimeDataType::JsonArray`) has a `Value::Null` parameter, `appfw_provider_postgres::param` previously bound the parameter as `Option<Vec<String>>::None`.

However, the SQL query generator renders `$N::jsonb[]` for the parameter placeholder. PostgreSQL strictly rejects this type mismatch at execution time:
```text
column "<column_name>" is of type jsonb[] but expression is of type text[]
```

#### Solution
In `appfw_provider_postgres/src/param.rs`, update the binding for `(RuntimeDataType::ObjectArray | RuntimeDataType::JsonArray, Value::Null)`:
```rust
(RuntimeDataType::ObjectArray | RuntimeDataType::JsonArray, Value::Null) => {
    let empty: Option<Vec<Json<Value>>> = None;
    query.bind(empty)
}
```
This correctly serializes the null parameter as `jsonb[]`, matching the query placeholder type annotation `$N::jsonb[]`.
