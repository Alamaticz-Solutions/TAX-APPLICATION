# ADR 0003: Relationship Source Of Truth

## Status

Accepted.

## Context

Entity-local navigation fields are convenient for generated GraphQL, but they
are a poor source of truth for relationship cardinality and storage. Directional
field names such as `NavToOne` and `NavToMany` describe one entity's view, while
domain relationships are schema-level facts.

## Decision

Relationships are authored as schema-level source objects. The generator uses
each relationship to project directional virtual navigation fields onto the
participating entity types.

Product developers define relationship endpoints, cardinality, storage, and
domain navigation field names in relationship config. Entity type files define
native scalar fields and physical foreign-key storage only.

Do not hand-author navigation properties in entity type config. `NavToOne` and
`NavToMany` are generated by `app_gen` from the schema-level relationship
source. `ManyToMany` is a schema relationship kind; it should not be authored as
an entity-local navigation field.

For many-to-many relationships, both sides receive `NavToMany`-style virtual
fields backed by the same junction/storage relationship definition.

Compatibility note: some generated runtime metadata still uses a `ManyToMany`
data type while the runtime normalization continues. That is an implementation
detail; the architectural model remains relationship-kind plus directional
navigation cardinality.

## Consequences

- Cardinality and storage ownership are defined once.
- Generated field consistency can be certified from relationship source through
  Query IR.
- Providers compile relationship projection and filtering from the same
  resolved relationship metadata.
- Hand-authored entity navigation fields should not drift from schema-level
  relationship definitions.
- Agents and developers edit one relationship definition instead of reconciling
  duplicated navigation intent across multiple entity files.
