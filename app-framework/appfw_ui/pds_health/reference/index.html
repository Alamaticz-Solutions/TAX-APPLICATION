Usage guidance

The catalog is product-neutral by design and should not include product routes, entities, or fixtures.

Theme Light and dark mode are driven by `data-theme` and canonical `--pds-*` tokens.
Density Compact is the default for enterprise grids; comfortable is available for lower-density workflows.
Accessibility Controls preserve native semantics, focus rings, keyboard operation, and screen-reader labels.
Examples Examples use generic work queues, requests, evidence, and review language only.

API reference contract

Enterprise-ready families must document API inputs, states, density and theme behavior, accessibility rules, usage, and verification evidence.

Checker enforced
Props Named inputs, variants, slots, callbacks, and generated metadata bindings stay visible to agents.
States Default, active, disabled, loading, invalid, empty, error, and selected states are documented by family.
Density Compact enterprise defaults and comfortable variants are explicit where layout density matters.
Accessibility Keyboard behavior, semantic roles, focus return, live regions, and named controls are part of the contract.
Usage Examples explain where products provide copy, generated contracts, routes, and data semantics.
Verification Each family maps to checker evidence, frontend tests, or product scaffold proof.
