# Precision Daylight Visual Language

Precision Daylight is implemented as the default **Apple-like** visual theme.
The theme name describes its luminous, translucent surface grammar; it does not
make vendor components or platform conventions part of the PDS contract. See
`visual-themes.md` for the independent visual-theme and color-mode axes.

Date ratified: 2026-07-16

Status: accepted PDS Health design-system direction. Product release readiness
still requires representative journey evidence.

## Intent

Light mode has its own art direction rather than behaving as a pale version of
dark mode. Its character is luminous, exact, dimensional, and technologically
distinctive without turning repeated work into decoration.

## Contract

- The canvas begins with a high-luminance blue-white and resolves toward
  near-white. It must not read as gray, beige, or a heavy blue field.
- Graphite typography and clear spacing carry hierarchy before borders,
  shadows, glow, or containment.
- Routine work surfaces use quiet white or translucent blue-white panels with
  restrained cool-neutral separation.
- Violet is reserved for intelligence-bearing content and bounded signals; it
  is not an ordinary page-background color.
- Repeated cards use modest elevation. Overlay depth remains reserved for
  transient content above the work plane.
- Slowly changing canvas light may provide atmosphere, but it cannot compete
  with reading, selection, focus, status, or action.
- Dark-theme values retain their own contrast and depth decisions rather than
  being mechanically inverted from light mode.

## Restraint Rules

- No decorative orbs, background blobs, ornamental illustration, novelty
  animation, or gray-tinted glass.
- No intelligence color on routine forms, grids, navigation, or content cards.
- No removal of labels, evidence, grounding, permission, or status semantics.
- Translucency must preserve text contrast against every supported canvas
  state and must fall back cleanly when backdrop filtering is unavailable.
- The visual language is not production evidence by itself.

## Verification

Retain desktop and mobile light/dark catalog captures, 200 percent zoom,
keyboard focus, reduced-motion, overflow, contrast, and serious/critical axe
evidence. Product adoption must additionally prove representative content,
performance, fallback, and repeated-work usability.
