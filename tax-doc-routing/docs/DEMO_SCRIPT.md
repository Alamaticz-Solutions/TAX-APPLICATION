# Tax Document Routing: demo script (about 10 minutes)

Rehearsed against the running app on 2026-10-16. Everything below was clicked through.

## Before you start (2 minutes)

1. Docker Desktop running, `tax-doc-routing-postgres` healthy (port 5434).
2. Backend on port 8090, frontend on port 5173 pointed at it:

   ```powershell
   # backend (from tax-doc-routing\backend)
   $env:ENV_NAME='local'; $env:API_PORT='8090'; $env:BACKEND_WORKER_STACK_MIB='128'
   $env:OKTA_AUDIENCE='api://default'; $env:OKTA_ISSUER='https://example.okta.com/oauth2/default'; $env:OKTA_CLIENT_ID='example-client-id'
   $env:APP_REQUEST_BODY_LIMIT_BYTES='4194304'   # lets a 2 MB PDF through once it is base64 encoded
   ..\target\debug\backend.exe

   # frontend (from tax-doc-routing\frontend)
   $env:VITE_BACKEND_URL='http://127.0.0.1:8090'; npm run dev
   ```
3. Open http://localhost:5173 in a window at least 1200px wide, light mode, 100% zoom (the sign-in brand panel only shows on wide windows).
4. Log in once as `alex` and `dana` to confirm both work, then log out.

Users (no password in local mode): `alex`, `sarah`, `mike`, `lisa` = Tax Staff; `dana` = Tax Admin.

## The story

"The tax department routes tax documents (K-1s, returns, statements) for owner doctors into the right client folders. Today that is a manual, Pega-based process. This is the new application: every request is tracked, failures are caught in a queue, and access is controlled by role."

## Script

### 1. Sign in (1 min), as `alex` (Tax Staff)
- Show the sign-in page. "Sign-in is checked against the real user table; the role and name come from the database, not from the screen."
- Try a wrong name (`nobody`) to show the rejection, then sign in as `alex`.

### 2. Dashboard (1 min)
- Point out the counts (Open / Processing / Exceptions / Completed) and "Work I need to do", showing only Alex's cases.
- "Every case has a human-friendly number, TD-1001 style, generated by the server."

### 3. Create a new request (3 min)
- **Create New Request** (top right).
- **Step 1, Client Info:** open Client Name, pick **John Smith**. "Everything fills in from the client reference table in the database: emails, folders." Leave Send Notification on Yes. Click **Create Request**. "The request now exists: it has its number, TD-xxxx, and its own temporary storage folder."
- **Step 2, Upload Documents:** drop two small PDFs (for example `K1_2025.pdf` and `TaxReturn_2025.pdf`; the AI reads the file **name**, so name them after the type). "Each file is stored in the request's temporary folder as soon as it is added. The AI suggests the type, year and entity; the user can correct any row with the pencil." Point at "Document Will Be Named": `Last, First - OriginalFileName`. Click **Submit**.
- **Step 3, Processing:** the nine steps tick through. "You can leave this page; processing continues and the case stays on your dashboard."
- **Step 4, Completed:** show the case number (for example TD-1036), Documents Filed 3, and the folders per document. "Which folders each document goes to comes from a rules table in the database: Form 8308 is external-only, so it gets one folder; K-1 gets three."

### 4. My Cases and Record Details (1 min)
- **My Cases**, search for the new TD number, click **View**.
- Show Overview (case summary, client details), Documents, Processing and Activity tabs.

### 5. Exception Task (1 min)
- **Exception Task**. "Anything that fails lands here, visible to every staff member. Records belonging to someone else show as Restricted, because staff only see their own cases."
- Mention the error types (Storage Folder Error, Processing Error, Invalid File Format).

### 6. Switch to admin (3 min): log out, sign in as `dana`
- Click the log-out icon (top right), sign in as `dana`. "Same screens, different permissions."
- The sidebar is the same three items, but the cases entry now reads **Request Management**. Dashboard says "team's activity summary".
- **Request Management:** every record across all staff, with an Assigned To column and an Assigned to filter (pick yourself for just your own). Open one in Open or In Progress state and show **Reassign** and **Cancel / Withdraw** (admin only). Demonstrate **Reassign** to another staff member (reversible). Do not click Cancel Confirm unless you want that case closed for good.
- **Exception Task**, open **TD-1012** and click **Retry failed step**. "The admin resolves it and processing resumes." (Do this once; it clears that exception.)
- The Administration page (read-only routing rules, taxpayers, entities) is hidden for now; it returns when editing is built.

### 7. Close (30 sec)
"Next phase is document storage: temp folder named with the case number, folder creation by year and document type, copy to Internal, External and Released to Client, then clean-up and the client email, same logic as the Pega process but on SharePoint. The design is done and waits on the client's SharePoint details."

## Be upfront about (do not claim these are live)

- **The AI prefill is a stand-in** (it reads the file name only). Uploads and filing are real, but until `STORAGE_PROVIDER=box` is set the files go to an in-memory store, so no real Box folder is created and the files vanish on restart (see docs/runbook/box-document-storage.md).
- **The filing steps are real saved progress** run on the server; with the in-memory store no real folders exist to look at.
- **"Client Notification: Sent" is the stored choice**, not an email actually sent; email is not built yet.
- **Document names** on the upload grid use the earlier convention; the agreed `Last, First - OriginalFileName.pdf` comes with the SharePoint work.
- Documents **are** saved with the case now: after a refresh the Documents tab and Filing Plan still show them.
- Login is local mode (user name only). Production uses Okta.

## Things that change data (plan for it)

- Creating a request adds a new TD case each time (rehearsal added TD-1034 and TD-1035).
- Retry clears an exception; Cancel closes a case permanently; Reassign changes the owner.
- Only three exceptions exist (TD-1010, TD-1011, TD-1012): retry at most one or two.
