[Heading 2] 3.5 Reference Class — TaxPayerRefData (Taxpayer Reference Table)
[] PDS-FW-Tax-Data-TaxPayerRefData is the master client registry. It holds one record per owner-doctor client and is the source of all client information that auto-populates on Tab 1 when a staff member creates a new routing record. It is maintained by administrators independently of the case workflow.
[Heading 3] Fields stored per client
[Heading 3] GetTaxPayerDetails — how data reaches the case
[] GetTaxPayerDetails is the Report Definition that populates the Tab 1 client dropdown. Key characteristics:
[] Source: alternate database (pyUseAlternateDB = true) — TaxPayerRefData is not stored in Pega's primary database; it lives in a separate data store
[] Filter: IsActive = 'YES' (case-insensitive) — inactive clients hidden
[] No search parameters — the entire active client list is returned on every Tab 1 load, sorted by FullName ascending
[] Max records: 100,000. Paging disabled. Full result set fetched into memory each time.
[] Fields returned: all 10 columns above except TaxPayerEntityType
[] Performance note: no search filter + paging disabled = full table scan on every new case creation. Consider adding a search-as-you-type filter or enabling paging if client volumes grow.
[Heading 3] Write-back — UpdatePayerRef_Info
[] After CheckClientBoxLocation verifies the client's Box folder URL, the system calls UpdatePayerRef_Info (activity on PDS-FW-Tax-Work-TDRouting). This writes updated credentials — the verified Box folder reference or Payer ID — back to the TaxPayerRefData record, keeping it current with any corrections made during the Re-enter URL loop.
[Heading 3] Security note — RW Password exposure
[] TaxPayerRWPassword is stored as plain text in the reference table and returned as a plain text field in GetTaxPayerDetails. It flows to the case clipboard without masking and is visible to any staff member with case access. Ensure the property is masked in all UI sections and excluded from case history capture.
[Heading 2] 3.6 Reference Class — TaxEntityList (Entity Reference Table)
[] PDS-FW-Tax-Data-TaxEntityList holds the master list of business entities (partnerships, corporations, personal corporations) associated with owner-doctor clients. When a staff member adds a document belonging to an entity on Tab 2, this table provides the searchable entity name dropdown. It is maintained by administrators independently of the case workflow.
[Heading 3] Fields stored per entity
[Heading 3] How entity data reaches the case — two reports, two purposes
[] GetTaxEntityList: the Tab 2 entity dropdown source. Returns all active entities from the standard Pega database, sorted alphabetically by EntityName. No parameters — full active list at once (max 10,000 records, paging disabled). Called from the TaxDocumentCollection section when a staff member selects an Entity Type.
[] D_FetchTax_EntityInfo (data page wrapping FetchTax_EntityInfo report): a thread-scoped data page with a single parameter (Oracle_ID). Returns only the EntityName for one specific entity. Called by the PopulateEntity_Name data transform on PDS-FW-Tax-Data-TaxDocument after a document row is saved. The data page never auto-refreshes (pyRefreshStrategy = never) — once loaded for a given OracleID it remains cached for the thread lifetime.
[Heading 3] OracleID — the external join key
[] OracleID is the sole custom property on this class. It is the primary lookup key across all entity reports and the join between Pega's entity list and the external Oracle master data system. When a staff member selects an entity on Tab 2, the OracleID is stored on the document row. PopulateEntity_Name then resolves the EntityName from it. OracleID also becomes the EntityTypeNumber component in the Box filename.
[Heading 3] Entity selection flow on Tab 2
[] Staff selects Entity Type — GetTaxEntityList fires with no parameters, returning all active entities sorted A-Z
[] Staff picks an entity name — OracleID stored on the document row
[] On document row save — D_FetchTax_EntityInfo(OracleID) called by PopulateEntity_Name to resolve and store EntityName
[] EntityName + OracleID feed into SetIFFileName — Box filename becomes: LastName, FirstName - {OracleID} {EntityName} - {Year} {DocType}.pdf
